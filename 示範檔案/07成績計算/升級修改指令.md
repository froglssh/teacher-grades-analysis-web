# 多班級成績管理系統 升級修改指令

目標檔案（同資料夾）：`多班級成績管理系統（claude優化版）.html`
單一 HTML 檔，約 4,280 行：CSS（行 9–441）、HTML（行 445–1109）、JavaScript（行 1111–4279）。
行號僅供初次定位，修改後會位移，請一律以**函式名稱**搜尋定位。

## 通則（每一批都適用）

1. **備份**：第 1 批開始前，若 `多班級成績管理系統（claude優化版）_備份_20261114.html` 不存在，先把目標檔原樣複製成該檔名。之後各批不再重複備份，也不得修改備份檔。
2. **只改目標檔**。不新增其他程式檔、不拆檔，維持單一 HTML。
3. **舊資料必須能開**：`STORE_KEY = 'lssh-score-mgr-v2'` 不可改名。新增的資料欄位一律在 `migrate()` 補預設值；舊版 JSON 備份也要能還原。
4. **不可刪除使用者資料**：任何會覆蓋或移除成績的動作都必須先確認，或可復原。
5. **輸出一律跳脫**：凡是把班名、姓名、欄名、群組名、分頁名寫進 `innerHTML` 的地方都用 `htmlEsc()`。
6. **介面文字用繁體中文**，沿用既有 CSS 變數與元件樣式（`.card`、`.tb-group`、`.print-modal-bg`、`.avgpanel` 等），不引入新的外部函式庫。
7. **每批完成後必做的檢查**：
   - 把 `<script>` 內容抽到暫存檔（放在系統暫存或 scratchpad，不要放進本資料夾），執行 `node --check` 確認語法無誤。
   - 用搜尋確認：被刪除或改名的函式已無任何殘留呼叫（含 HTML 內的 `onclick`）。
   - 在檔案頂部版本標示與「使用說明」區塊補上本批新功能的說明。
8. **每批結束回報**：已完成項目、未完成或刻意略過的項目與原因、執行過的檢查及結果。不要把沒驗證的事說成已驗證。
9. 只做本批指定的項目，不要順手做後面批次的內容。

## 第 1 批：資料遺失與計算錯誤（最優先）

### 1.1 單一計算函式
現況：加權總分在 `recalcRow`、`semesterScores`、`updateFooter`、`buildPrintPage`、`classRows` 各算一次，規則不一致。

新增並讓上述五處全部改用：

```js
// 回傳某生的完整計算結果
function computeStudent(c, k) -> {
  vals,          // {colId: 數值或 null}，平均欄為 computeAvg 結果
  total,         // Σ v × 配分/100（含個別配分），未取整
  filledWeight,  // 有成績的欄位配分合計
  totalWeight,   // 所有配分>0 欄位的配分合計
  any,           // 是否至少有一筆成績
  adj,           // 加減分
  final          // any ? roundScore(clamp(total+adj, 0, 100)) : null
}
function roundScore(v)   // 取一位小數：Math.round((v + 1e-9) * 10) / 10
```

- `semesterScores(c)` 改為回傳 `computeStudent(...).final`，**完全沒有成績的學生回傳 `null`**（現況是 0，會拉低平均、灌進不及格名單）。所有呼叫端都要能處理 `null`（統計略過、列印與匯出顯示空白、名次顯示「–」）。
- 及格判定、畫面顯示、統計、列印、匯出**全部使用同一個取整後的 `final`**。現況 `recalcRow` 用未取整的值判斷紅字、顯示卻用 `toFixed(1)`。
- 列印與匯出的「加權總分」改用 `computeStudent().total`，才會套用個別配分。
- 把 v3 區段對 `recalcRow`、`renderTable`、`onScoreInput`、`scEnter`、`renderSingleStats` 的「覆寫包裝」保留不動（第 5 批才整理），但其內部計算同樣改用 `computeStudent`。

### 1.2 `migrate()` 不得刪欄位
`migrate()` 目前每次開啟都刪掉「假期作業」以及「期中考群組、名稱以 3 結尾或含第三次」的欄位與成績。移除這段刪除邏輯（含連帶刪平均欄來源、刪成績的部分）。保留：`小考N` → `N` 的改名、`期中考試` → `期中考` 的群組簡化。

### 1.3 批次貼上 `applyBatch` 重寫
- 若貼上資料第一欄全是整數且能對上本班座號，就**依座號對位**，其餘欄才是成績；否則依列序對位。
- 第一列若所有格子都不是數字，視為標題列並略過。
- 每格用 `parseScoreText` 驗證；不合法的格子略過並計數。
- **空白格不動原成績**（現況會刪除）。
- 寫入一律經過 `setScore(k, colId, v, batch)`，結束後 `pushUndo(batch)`，可用 Ctrl+Z 復原。
- 完成訊息列出：寫入幾筆、覆蓋幾筆、略過幾筆、對位方式（座號／列序）。

### 1.4 覆蓋前確認
新增通用對話框（沿用 `.print-modal-bg` 樣式）：

```js
function askChoice(title, messageHtml, buttons) -> Promise<string|null>
// buttons: [{value, label, cls}]；按 Esc 或點背景回傳 null
```

- `doImport()`：若要匯入的班級 key 已存在，先列出這些班級，提供「覆蓋這些班級／只匯入新班級／取消」。
- `importJSON()`：改用 `askChoice` 三個按鈕「合併到現有資料／全部取代／取消」。現況用 `confirm`，按「取消」反而清空全部資料，必須改掉。

### 1.5 `updateStudents()` 不得靜默丟成績
- 新舊名單配對順序：座號＋姓名相同 → 姓名相同且唯一（視為換座號）→ 座號相同（視為改名）。
- 配對到的學生，把 `scores`、`adjustments`、`personalWeights` 全部搬到新的 sid。
- 保留原本的 `gender`（現況會清空）。
- 若有舊學生配對不到且該生有成績，先用 `askChoice` 列出姓名與筆數，確認後才移除。

### 1.6 儲存失敗要看得到
`saveAll()` 的 `catch`：不論是否手動，都把 `#saveBadge` 改成紅底「⚠ 儲存失敗」，並 `toast` 提示原因與「請立即下載 JSON 備份」。成功時恢復原樣。

### 1.7 成績分布漏掉小數
新增 `binCounts(scores, width=10)`：以 `Math.min(Math.floor(v / width), 100/width - 1)` 分組。`renderSingleStats` 的分布圖與 `buildPrintPage` 的分布表都改用它。現況以 `s>=lo && s<=hi` 比對整數上下界，59.5 之類的成績不屬於任何區間。

### 1.8 平均欄重複計分
- `createAvgColumn()`：若來源欄有配分 > 0，建立時把它們歸零，並在訊息中說明。
- `updateWeightPill()`：若任一平均欄配分 > 0 且其任一來源欄配分也 > 0，總配分標籤顯示為警示狀態，文字加「⚠ 重複計分」，`title` 列出是哪些欄。

### 1.9 個別配分說明文字
個別配分視窗的提示改為：「空白＝使用班級配分；填 0＝此項不計入該生成績。」（程式行為不變，現有說明寫反了。）

### 1.10 名次與百分位數統一
- 新增 `rankList(values)`：同分同名次（競賽排名 1,2,2,4），`null` 回傳 `null`。成績表名次欄、統計排行、列印名次全部改用。現況列印名次用排序索引，同分會不同名次。
- 百分位數只留 `pctInterp`（線性內插）一種。`describe()` 的 `q1`、`q3` 與 `buildPrintPage` 的 25／75 分位都改用它。列印的統計摘要直接呼叫 `describe()`，不要自己再算一次。

### 1.11 長期追蹤放寬名單檢查
`renderTrack()`：以所有所選班級**共同出現的姓名**為分析對象。
- 與基準班的重疊率 ≥ 80%：照常分析，只計共同學生；結果上方顯示提醒與差異名單（各班多出或缺少的姓名）。
- 重疊率 < 80%：維持現況，擋下並顯示對照表。

## 第 2 批：計算方式升級

### 2.1 缺考與免計
- 資料：`c.marks = { sid: { colId: 'abs' | 'ex' } }`。`abs`＝缺考以 0 分計；`ex`＝免計。
- 輸入：成績格輸入「缺」或「免」（也接受 `a`、`e`）即設定標記並清除該格數值；輸入數字則清除標記。格子顯示「缺」「免」，並有不同底色。快速登分與貼上同樣接受。
- 計算（`computeStudent`）：`abs` 視為 0 且算已填；`ex` 不計，且該生成績按比例放大：`total × totalWeight / (totalWeight − 免計欄配分合計)`。
- 平均欄：來源中的 `abs` 以 0 計入，`ex` 與空白不計。
- 統計單項：`abs` 以 0 計，`ex` 不列入。列印、Excel、TSV 顯示「缺」「免」文字。
- 復原要涵蓋標記變更。

### 2.2 目前累計
`computeStudent` 增加 `cumulative = filledWeight > 0 ? roundScore(total / filledWeight × 100) : null`。
- 成績表右側新增「目前累計」欄，排在「初步成績」之前；表尾統計列同步。
- 統計依據、多班比較項目各增加「目前累計（已登記項目換算）」。
- 「學期成績」欄的紅字規則：只有當 `filledWeight ≥ totalWeight`（全部登記完）或老師已輸入加減分時才標不及格紅字；否則以淡色顯示，避免學期中全班一片紅。

### 2.3 欄位滿分
- 欄位新增 `max`（預設 100）。「新增成績欄位」面板加「滿分」輸入框。
- 該欄輸入驗證範圍為 0–`max`；計入學期成績時以 `v / max × 100` 換算。
- 單項統計以原始分呈現，及格線為 `max × 及格分數/100`。平均欄以換算後的百分制計算。
- 欄位標題在滿分不是 100 時顯示「/50」之類的小字。（修改既有欄位滿分的介面在第 3 批的欄位選單。）

### 2.4 計算設定
- 全域 `settings = { decimals: 1, passMark: 60, enterMode: 'nextEmpty' }`，與 `classes` 一起存進同一個 localStorage 項目，JSON 備份也帶上。
- `roundScore` 依 `settings.decimals`（0 或 1）取整；所有寫死的 `60` 改用 `settings.passMark`。
- 工具列「檢視」群組加「⚙ 計算設定」按鈕，開啟視窗設定：學期成績小數位（整數／一位）、及格分數。變更後重算並重繪。

### 2.5 群組配分
- 平均欄新增屬性 `autoGroup: true|false`。為 `true` 時，來源自動等於同群組內所有手動欄，新增或刪除欄位後自動更新。
- `avgMode` 擴充為 `'all' | 'dropN' | 'topN'`（N 為正整數，用正規式解析；相容既有 `drop1`、`drop2`）。平均欄建立面板的下拉選單同步增加「取最高 N 次」，N 可輸入。
- 工具列「欄位」群組加「⚖ 群組配分」按鈕，開啟視窗：每個群組一列，填「群組配分 %」與「計算方式」（各欄各自配分／全部平均／去最低 N 次／取最高 N 次）。套用後：選平均類方式的群組，建立或更新該群組的 `autoGroup` 平均欄（命名「日常考查平均」等），配分設為群組配分，來源欄配分歸零；選「各欄各自配分」則不動。視窗底部即時顯示合計是否為 100%。

### 2.6 加減分
- 加減分輸入框由 `type=number` 改為文字型（`inputmode="numeric"`），滑鼠滾輪不再誤改；仍只接受整數。
- 加減分變更納入復原。
- `c.adjNotes = { sid: '理由' }`：在加減分格按兩下可輸入理由；有理由時格子右上角顯示小圓點，`title` 顯示內容；列印與 Excel 匯出增加「加減分說明」欄（全班都沒有說明時不輸出此欄）。

### 2.7 匯入後預設配分補滿
`applyDefaultWeights()`：套完段考預設配分後，若有日常考查手動欄且總配分 < 100，建立一個 `autoGroup` 的「日常考查平均」欄，配分為剩餘的百分比。

## 第 3 批：輸入、欄位與介面

### 3.1 復原機制擴大
- 復原堆疊改為每個班級各一份（以班級 key 為索引的 Map），切換班級不清空。
- 新增快照式復原 `snapshotUndo(label, keys)`：在結構性操作前深拷貝受影響的班級。適用：刪除欄位、改配分、群組配分、複製配分、批次貼上、上傳成績檔、更新名單、改欄位屬性。上限 30 筆。既有逐格復原維持原樣，兩種紀錄放同一堆疊。
- 復原提示顯示該筆操作名稱（例如「已復原：刪除欄位『小考3』」）。

### 3.2 寫入前預覽
`doUploadImport()` 與 `applyBatch()` 在寫入前先算出「新增 N 筆、覆蓋 M 筆（列出前 5 筆的座號、姓名、舊值→新值）、略過 K 筆」，用 `askChoice` 確認後才寫入。超出範圍的數值不寫入並計入略過。

### 3.3 連續登分模式
快速登分面板加「連續模式」勾選與「起始座號」：
- 勾選後輸入框只需輸入分數，Enter 寫入目前座號並跳到下一位；面板以大字顯示「下一位：05 王小明」。
- 直接按 Enter（空白）＝跳過此人；輸入「缺」「免」同 2.1；輸入 `b` 回上一位。
- 到最後一位時提示完成並列出未登分座號。

### 3.4 Enter 行為可切換
狀態列加切換鈕，對應 `settings.enterMode`：`nextEmpty`（跳到下方第一個空格，現況）／`down`（單純往下一列）。

### 3.5 欄位選單
每個欄位標題加「⋯」按鈕，開啟小選單（點外面或 Esc 關閉）：名稱、群組、配分、滿分、日期（選填，`col.date`）、左移、右移、加入平均欄…（進入現有選取模式並預先勾選此欄）、刪除欄位。
- 移除工具列的「🗑 刪除欄位」模式按鈕與 `editMode` 相關程式。
- `sortColumns` 維持群組順序，群組內順序由左移／右移決定。
- 欄位配分輸入框字級由 10px 提高到 12px。

### 3.6 群組可自訂
新增欄位面板與欄位選單的群組下拉選單：日常考查、作業、實驗、報告、學習態度、期初考、期中考、期末考、以及班上已存在的其他群組名稱，最後一項「自訂…」可輸入新名稱。`COL_GROUP_CLASS` 與 `GROUP_ORDER` 為新群組補上顏色與順序（實驗、報告、學習態度排在作業之後）。

### 3.7 群組折疊與右側固定
- 點群組色帶可折疊該群組：隱藏其手動欄，只留平均欄與一個窄的「▸ N 欄」佔位欄。狀態存在 `c.collapsed`。
- 右側「目前累計、初步成績、加減分、學期成績、名次」改為 `position: sticky; right: …` 固定，橫向捲動時仍看得到。確認與左側固定欄、表頭、表尾的層級不互相遮蓋。

### 3.8 欄名重複
新增或改名時，若同班已有同名欄，自動加上「(2)」之類的後綴並提示。

### 3.9 匯入規則
- 匯入卡片加兩個勾選項（預設勾選）：「略過假期作業欄位」「略過第三次期中考」。`parseGradeSheet(ws, opts)` 依此決定，變更勾選時重新分析預覽。
- `parseGradeSheet` 比對「座號」「姓名」「性別」前，比照 `usParseWorkbook` 去除空白與換行。
- 預設學年不再寫死 114：`月份 ≥ 8 ? 西元年 − 1911 : 西元年 − 1912`，用於匯入與手動新增班級。

### 3.10 介面整理
- 啟動時若已有班級資料，預設開在「成績管理」分頁。
- 移除學期選取列的「★ 全選此學期」按鈕及 `cpSelectAllSem`。
- 「已儲存的班級資料」：每個班級項目加「開啟」按鈕；移除底部「載入勾選的班級」按鈕與 `doLoadFromStore`；勾選框只用於批次刪除。
- 四個面板（快速登分、建立平均、新增欄位、批次貼上）改由單一函式 `openPanel(id)` 控制，同時只開一個。
- 工具列「檢視」群組的縮放、高度、儲存收進一個可展開的「檢視選項 ▾」。
- `toast`：停留時間依字數調整（最短 2.2 秒、最長 7 秒）；每則訊息同時寫入操作紀錄（最多 50 筆），點右上角儲存標籤可開啟紀錄視窗。
- 所有視窗支援 Esc 與點背景關閉。
- 不及格除了紅字，另加「▾」符號，不單靠顏色區分。
- 列印：欄位數超過 12 時注入 `@page { size: A4 landscape; }`。

### 3.11 刪除改為可還原
刪除班級、刪除學期、清除所有資料：被刪的班級先移入 `trash`（最多保留 20 筆，含刪除時間），存在同一個 localStorage 項目。「匯出資料」分頁新增「最近刪除」區塊，可逐筆還原或永久刪除。

## 第 4 批：統計擴充

### 4.1 分布圖
組距可選 5 或 10 分；以自訂 Chart.js plugin 畫出及格線與平均線（含文字標示）。顏色以及格線為界。

### 4.2 標準化分數
單一班級排行表加「Z 分數」與「T 分數」（T = 50 + 10Z）兩欄；標準差為 0 時顯示「–」。

### 4.3 多班比較盒鬚圖
多班比較新增圖表切換「平均±標準差／盒鬚圖」。盒鬚圖用 Chart.js 浮動長條（Q1–Q3）加自訂 plugin 畫中位數線與最小、最大鬚線，不引入新函式庫。

### 4.4 性別比較
班級有性別資料時，單一班級統計增加一張表：各性別的人數、平均、標準差、及格率。

### 4.5 項目分析表

## 第 6 批：改用 IndexedDB 儲存（4.0 → 4.1）

開始前先把目前的目標檔複製為 `多班級成績管理系統（claude優化版）_備份_4.0_20261115.html`（已存在就跳過）。原有的 `…_備份_20261114.html` 不要動。

### 6.1 儲存層
把目前直接讀寫 localStorage 的 `saveAll`／`loadAll` 改為經過一個儲存層：

- **主要儲存**：IndexedDB，資料庫名 `lssh-score-mgr`，物件倉儲 `kv`，鍵 `state`，值為與現在相同的整包狀態物件（classes、curKey、settings、trash、backup…），另加 `savedAt`（毫秒時間戳）與 `rev`（每次儲存遞增的整數）。
- **鏡像**：每次儲存也盡力寫一份到 localStorage 的 `lssh-score-mgr-v2`（同樣帶 `savedAt`）。寫入失敗（超過容量、被停用）時靜默略過，不算儲存失敗，但在儲存資訊中標示「鏡像已停止」。
- **後援**：IndexedDB 無法開啟或寫入失敗時，退回只用 localStorage，行為與 4.0 相同，並在儲存資訊中標示目前使用的是後援模式。兩者都失敗才顯示紅色「⚠ 儲存失敗」。
- `STORE_KEY` 名稱不可改。

### 6.2 載入與搬移
- 啟動改為非同步：讀取完成前顯示「載入資料中…」，完成後才做第一次繪製。讀取期間不可觸發任何儲存（避免空狀態蓋掉資料）。
- 取 IndexedDB 與 localStorage 兩邊的狀態，用 `savedAt` 較新的一份；沒有 `savedAt` 的舊資料視為最舊，但只要另一邊是空的就採用它。
- 第一次由 localStorage 搬到 IndexedDB 時：寫入後讀回比對班級數與成績筆數一致才算成功，並在操作紀錄留一筆「已將資料搬移到 IndexedDB」。**不可刪除 localStorage 的原資料。**
- 載入後照常執行 `migrate()`。

### 6.3 寫入安全
- 儲存改為序列化佇列：同時只有一個寫入在進行，期間的多次請求合併成最後一次。
- `visibilitychange` 變為 hidden 與 `pagehide` 時立刻送出尚未寫入的變更（IndexedDB 與 localStorage 鏡像都寫）。
- 多分頁保護：寫入前讀取資料庫內的 `rev`，若比本頁上次載入或寫入的 `rev` 新，表示另一個分頁改過資料。此時暫停寫入並用 `askChoice` 詢問「重新載入最新資料／以本頁內容覆蓋／先下載本頁 JSON 備份」。另用 `BroadcastChannel`（可用時）在其他分頁儲存後提示本頁。
- 啟動後呼叫 `navigator.storage.persist()`（可用時），結果只顯示在儲存資訊中，不彈出訊息。

### 6.4 自動還原點
- 物件倉儲 `snapshots`：每天第一次成功儲存時留一份完整狀態（鍵為日期），保留最近 7 份，較舊的自動刪除。「清除所有資料」「JSON 全部取代」執行前也各留一份（鍵加上時間與原因）。
- 「匯出資料」分頁新增「自動還原點」區塊：列出日期、班級數、成績筆數，可「還原」（用 `askChoice` 確認，還原前先把目前狀態存成一份還原點）或「下載為 JSON」。IndexedDB 不可用時顯示說明而不是空白。

### 6.5 儲存資訊
「匯出資料」分頁新增「儲存狀態」區塊：目前儲存位置（IndexedDB／後援 localStorage）、鏡像是否正常、資料大小、瀏覽器配額用量（`navigator.storage.estimate()` 可用時）、是否已取得持久儲存、最後儲存時間。

### 6.6 其他
- JSON 備份與還原的格式不變，4.0 的備份檔要能還原。
- 使用說明補上：資料改存 IndexedDB、容量不再受 5MB 限制、自動還原點、升級後不要再用舊版檔案登分（舊版只會讀寫 localStorage，兩邊會不同步）、資料仍只存在這台電腦的這個瀏覽器所以仍需定期下載 JSON 備份。
- 版本標示改為 4.1。

### 6.7 測試（用 Playwright 加本機 Chrome、暫時 context；需涵蓋以 `file://` 開啟的情況）
- 全新開啟、登分、重新整理後資料仍在。
- 只有舊 localStorage 資料（4.0 格式與不含 `settings`／`trash`／`backup` 的更舊格式）時，搬移後資料完全相同，localStorage 原資料仍在。

## 第 8 批：指定資料夾儲存，兩台電腦共用（4.2 → 4.3）

使用情境：老師有兩台電腦，都透過共用雲端硬碟（Google Drive 電腦版）開啟同一個資料夾裡的這支程式。希望成績資料存成資料夾裡看得到的檔案，兩台電腦讀寫同一份，老師也知道原始資料在哪裡、如何搬移。

開始前先把目前的目標檔複製為 `多班級成績管理系統（claude優化版）_備份_4.2_20261115.html`（已存在就跳過）。其他備份檔不要動。

注意：目標檔末端有兩行各數百 KB 的內嵌函式庫（`LIB:xlsx`、`LIB:chart` 標記區塊）。讀檔一律用 offset/limit 避開；不要改動這兩個區塊。

### 8.1 技術與架構
- 使用 File System Access API（`showDirectoryPicker`、`FileSystemDirectoryHandle`）。只有 Chrome、Edge 支援；不支援的瀏覽器顯示說明，其餘功能照舊。
- 先確認 API 在 `file://` 開啟時是否可用（`'showDirectoryPicker' in window`、`isSecureContext`），把結果寫進回報。
- 資料夾代碼（handle）存進 IndexedDB 的 `kv` 倉儲（鍵 `folderHandle`），下次開啟可重新取用。
- **連結資料夾後，資料夾內的檔案是唯一正本**；IndexedDB 與 localStorage 鏡像降為本機快取與離線後援，照常寫入。
- 未連結資料夾時，行為與 4.2 完全相同。

### 8.2 資料夾內的檔案
- `成績資料.json`：正本。格式與現有 JSON 備份相容（可用「還原 JSON 備份」讀入），另加 `savedAt`、`rev`、`savedBy`（裝置名稱）、`appVersion`。
- `成績資料_歷史/成績資料_YYYYMMDD.json`：每天第一次寫入正本前，把當時資料夾裡的正本複製一份到此子資料夾，保留最近 14 份。
- 衝突時另存的檔案：`成績資料_衝突_<裝置名稱>_<YYYYMMDD-HHmm>.json`。
- 寫入用 `createWritable()`，寫完 `close()` 才算成功。寫入失敗不可留下半截檔案覆蓋正本。

### 8.3 裝置名稱
每台電腦一個名稱，存在 localStorage 的獨立鍵（不隨資料同步），預設「電腦-」加四碼隨機字。可在設定區修改（例如「辦公室」「家裡」）。寫入正本時記在 `savedBy`。

### 8.4 介面
「匯出資料」分頁的「儲存狀態」區塊擴充為「資料存放位置」：
- 未連結：說明目前資料只存在本機瀏覽器，按鈕「📁 選擇資料存放資料夾」。旁邊一句建議：選擇與本程式相同的雲端硬碟資料夾，另一台電腦也選同一個。
- 已連結：顯示資料夾名稱（瀏覽器不提供完整路徑，請在說明中註明「請記下您選的是哪個資料夾」，並提供一個可自由填寫的「位置備註」欄位讓老師自己記路徑，存在正本檔內）、正本檔名、最後寫入時間與裝置、歷史備份份數；按鈕「更換資料夾」「中斷連結」「立即寫入」「從資料夾重新載入」。
- 頁首儲存標籤旁加一個小標籤顯示狀態：`📁 已同步到資料夾`／`📁 需要重新授權`／`📁 寫入失敗`／（未連結時不顯示）。點擊前往上述區塊。
- 首次連結的流程（用 `askChoice`）：
  - 資料夾內沒有 `成績資料.json`：把目前資料寫進去。
  - 資料夾內已有、本機沒有資料：直接載入。
  - 兩邊都有資料：顯示兩邊的班級數、成績筆數、最後儲存時間與裝置，選「使用資料夾內的資料」「用本機資料覆蓋資料夾」「取消」。被取代的一方先存成自動還原點（本機）或衝突檔（資料夾）。

### 8.5 開啟時
- 有已存的資料夾代碼時，用 `queryPermission({mode:'readwrite'})` 檢查。
  - 已授權：讀取正本。正本比本機新（比較 `rev` 與 `savedAt`）就載入正本；本機比正本新（例如上次沒連上時在本機改過）就用 8.4 的兩邊比較對話框詢問。
  - 需要授權（瀏覽器規定要使用者點擊）：頁面頂端顯示醒目提示列「點此連接成績資料夾『名稱』」。**連接完成並比對過正本之前，畫面上方持續提示目前顯示的是本機快取，可能不是最新。** 點擊後 `requestPermission`，再走上面的比對。
  - 資料夾已不存在或讀取失敗：提示並保持使用本機資料，不清除代碼，讓老師可以重試或更換。
- 這些流程都要接在第 6 批的非同步啟動之後，讀取完成前不可觸發任何儲存。

### 8.6 寫入時
- 每次儲存成功（IndexedDB 那一層）之後，延遲約 2 秒合併寫入正本；序列化，同時只有一個寫入。
- **寫入前先檢查正本是否被別台電腦改過**：讀取檔案的 `lastModified` 與內容中的 `rev`／`savedAt`／`savedBy`，與本頁上次讀取或寫入時記下的值比對。不同就暫停寫入，用 `askChoice` 詢問：
  - 「載入資料夾內較新的資料」（本頁未寫入的內容先存成本機自動還原點）
  - 「以本頁內容覆蓋」（資料夾內原檔先另存為衝突檔）
  - 「把本頁內容另存成衝突檔，之後再處理」
- 頁面重新取得焦點時、以及每 60 秒，檢查正本的 `lastModified`。若已被別台電腦更新且本頁沒有未寫入的變更，頂端顯示「另一台電腦（裝置名稱）已於某時更新資料」與「載入最新資料」按鈕；本頁有未寫入變更則走上面的衝突詢問。
- 分頁隱藏或關閉時盡力把未寫入的變更寫入正本（無法保證完成；本機 IndexedDB 與鏡像仍會保住資料，下次開啟時由 8.5 的比對處理）。
- 寫入失敗（權限被收回、磁碟離線、雲端硬碟未啟動）：標籤變為「📁 寫入失敗」，提示一次，資料仍存在本機；之後每次儲存重試。

### 8.7 中斷與更換
- 「中斷連結」：刪除已存的資料夾代碼，資料夾內的檔案不動，本機資料保留。
- 「更換資料夾」：選新資料夾後走 8.4 的首次連結流程；舊資料夾的檔案不動。說明文字告訴老師：要搬移資料，直接在檔案總管／Finder 把 `成績資料.json` 與 `成績資料_歷史` 資料夾搬到新位置，再用「更換資料夾」指向新位置即可。

### 8.8 使用說明
在頁內「使用說明」新增一節「兩台電腦共用資料」，用老師看得懂的話寫清楚：
- 設定步驟：兩台電腦各自按一次「選擇資料存放資料夾」，選同一個雲端硬碟資料夾。
- 每次開啟可能需要點一下授權；Chrome 出現「每次造訪都允許」的選項時可勾選。
- 原始資料就是資料夾裡的 `成績資料.json`，歷史備份在 `成績資料_歷史`。
- 雲端硬碟同步需要時間：換電腦前先確認這台已顯示「已同步到資料夾」並等雲端硬碟上傳完成；不要兩台同時開著登分。出現衝突詢問時各選項的意思。
- 只有 Chrome、Edge 支援此功能。
- 版本標示改為 4.3。

### 8.9 測試
原生資料夾選擇視窗無法由自動化工具操作。測試時以替身取代 `showDirectoryPicker`（例如回傳 OPFS `navigator.storage.getDirectory()` 下的子資料夾代碼，介面相同；OPFS 在 `file://` 不可用時改用本機 http 伺服器提供頁面來測這部分），並在回報中明說真實選擇視窗與真實 Google Drive 資料夾沒有測到。需涵蓋：
- 首次連結的三種情況（資料夾空、本機空、兩邊都有與三個選項）。
- 登分後正本內容正確、可用「還原 JSON 備份」讀回、4.2 產生的 JSON 備份放進資料夾當正本也能載入。
- 模擬第二台電腦（另一個 context、不同裝置名稱、同一個資料夾）：A 寫入後 B 取得焦點看到更新提示並載入；A、B 都有變更時的衝突詢問三個選項與衝突檔內容。
- 重新開啟時已授權、需要授權（替身讓 `queryPermission` 回傳 `prompt`）、資料夾讀取失敗三種情況；授權前確實沒有寫入正本。
- 每日歷史備份的產生與保留 14 份。
- 寫入失敗（替身讓 `createWritable` 丟錯）時的提示、本機資料仍在、之後恢復可重試成功；失敗時正本內容未被破壞。
- 中斷連結、更換資料夾。
- 不支援 API 的瀏覽器（刪除 `showDirectoryPicker`）顯示說明且其他功能正常。
- 未連結資料夾時，重跑第 6、7 批測試與既有回歸測試，結果與 4.2 相同。
